<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Backend | JWT token in Authorization header validates user identity |
| Backend → Database | User ownership verified before returning demo data |
| Client → Demo Viewer | User owns demo before allowing playback (middleware + API validation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-14 | Information Disclosure | Cross-user demo access | mitigate | Backend validates JWT steam_id matches demo.user_id before returning data. Test confirms user cannot access other users' demos. |
| T-14-15 | Denial of Service | Public metrics calculation | mitigate | Metrics cached in Redis with 1-hour TTL. Calculation runs hourly via scheduled command (not on request). |
| T-14-16 | Tampering | Demo upload auto-assignment | mitigate | Demo.user_id set from JWT claims (authenticated session), not user input. User cannot upload on behalf of another user. |
| T-14-17 | Elevation of Privilege | User pagination access | accept | Pagination params (page, limit) are query-safe. Cannot enumerate all users or all demos (filtered by authenticated user). |
| T-14-18 | Repudiation | Demo upload events | accept | Demo.created_at timestamp and user_id recorded. For audit logs, Phase 15+ can add audit table. |

</threat_model>
