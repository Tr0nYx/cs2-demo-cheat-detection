<objective>
Create Symfony User entity and refresh token persistence layer for authentication.

Purpose: This wave persists authenticated users in PostgreSQL and tracks refresh tokens for session management. It includes User entity with Doctrine ORM, database migrations, and repository methods for querying users by steam_id. Integration with Wave 2's SteamVerifyHandler ensures users are created/updated on login.

Output: User table (`app_user`) and refresh token table (`app_user_refresh_tokens`) in PostgreSQL. UserRepository provides find/create/update methods. All changes tested with unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Incoming JWT → Database | JWT claims validated against stored User record before operations |
| Steam API Response → Database | User data from Steam API stored in database after validation |
| Refresh Token Storage → API | Refresh tokens stored as hashes (never plaintext) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-10 | Information Disclosure | Plaintext refresh tokens | mitigate | Store only SHA256 hash of refresh token. Incoming token hashed before lookup. Original token never stored in DB. |
| T-14-11 | Tampering | User avatar_url | mitigate | Validate URL is HTTPS only (reject HTTP from Steam API). Update avatar_url from Steam API only on login. |
| T-14-12 | Denial of Service | Token table growth | mitigate | Run cleanup job to delete expired tokens. Add index on expires_at for efficient cleanup query. |
| T-14-13 | Elevation of Privilege | User role/permissions | accept | User entity has no role field; all users have equal permissions. Admin features deferred to Phase 15+. |

</threat_model>
