Create `symfony/src/Infrastructure/Steam/SteamOpenIdValidator.php`:
- Implement OpenID 2.0 assertion validation (backend-side, NOT client-side)
- Method: `validateOpenIdAssertion(array $queryParams): string` (returns steam_id)
- Validates OpenID protocol:
  - Check openid.ns is correct
  - Verify openid.identity matches claimed_id
  - Validate openid.sig signature using openid.assoc_handle
  - For development, use HTTP; for production, require HTTPS
- Fetch user profile from Steam Web API:
  - GET https://api.steampowered.com/ISteamUser/GetPlayerSummaries/v0002/?key={STEAM_API_KEY}&steamids={steam_id}
  - Extract: steam_id, personaname (username), avatar (avatar_url)
- Return validated steam_id on success
- Throw exception with clear message if validation fails

Create `symfony/src/Application/Auth/SteamVerifyRequest.php`:
- DTO to hold OpenID query parameters from next-auth callback
- Fields: openid_ns, openid_identity, openid_claimed_id, openid_mode, openid_sig, openid_assoc_handle, etc.
- Use Symfony validator attributes for optional validation

Create `symfony/src/Application/Auth/SteamVerifyHandler.php`:
- Handle the Steam verification request
- Constructor: Inject SteamOpenIdValidator, JwtTokenService (to be created in Wave 3 or use default), logger
- Method: `handle(SteamVerifyRequest $request): array`
  - Call SteamOpenIdValidator->validateOpenIdAssertion()
  - Fetch user profile from Steam API
  - Return: { steam_id, username, avatar_url, access_token, refresh_token, expires_at }
  - Token generation logic: access token expires in 1 day, refresh token in 30 days
  - For now, sign tokens with a simple HS256 algorithm (NEXTAUTH_SECRET)

Create `symfony/src/Controller/AuthController.php`:
- POST `/api/auth/steam-verify`

  - Accepts { refreshToken } in body
  - Validates refresh token (simple check for now; Wave 3 improves this)
  - Returns { access_token, refresh_token, expires_at } (rotates refresh token)
  - Returns 401 if token invalid/expired

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → Steam | OpenID assertion sent to Steam for validation (Steam-controlled, external) |
| Client → Backend | OpenID assertion forwarded to backend for signature validation |
| Backend → Steam API | Backend calls Steam Web API to fetch user profile (authenticated with API key) |
| Backend → Client | JWT tokens returned in response; stored in httpOnly cookies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-04 | Spoofing | OpenID assertion validation | mitigate | Backend validates OpenID signature using Valve's public keys before accepting steam_id. Never trust client-provided steam_id. |
| T-14-05 | Tampering | JWT tokens in cookies | mitigate | HttpOnly flag prevents JS access. Secure flag (production only) prevents HTTP transmission. SameSite=Strict prevents CSRF token theft. |
| T-14-06 | Repudiation | User login events | accept | Login is auditable via logs; JWT contains steam_id. For Phase 15+, add login audit table if needed. |
| T-14-07 | Information Disclosure | Steam API key exposure | mitigate | API key stored in server-side .env only (never sent to client). Rate limit API calls to Steam to prevent enumeration. |
| T-14-08 | Denial of Service | `/api/auth/steam-verify` endpoint | mitigate | Rate limit to 10 requests/minute per IP. OpenID validation is CPU-bound; validate timeout (5 sec). Reject malformed OpenID assertions early. |
| T-14-09 | Elevation of Privilege | JWT token scope | mitigate | Token contains steam_id only; no admin claims. Backend validates steam_id matches user on protected endpoints. |

</threat_model>
