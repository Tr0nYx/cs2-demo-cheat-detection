### Task 1: Create Types & React Query Hook

**Files:**
- `nextjs/types/api.ts` (update or create)
- `nextjs/hooks/useTraceQuery.ts` (new)

**Purpose:** Type-safe integration with Wave 1 API endpoint.

**What to build:**

**1. Update `nextjs/types/api.ts`** with TRACE types:
```typescript
interface TraceComponentDto {
  ekill: number;   // [0.3, 2.0]
  aim: number;     // [0.3, 2.0]
  kast: number;    // [0.3, 2.0]
  util: number;    // [0.3, 2.0]
  clutch: number;  // [0.3, 2.0]
}

interface TraceDto {
  traceBase: number;           // float
  traceAdjusted: number;       // float
  traceNormalized: number;     // float
  trustMultiplier: number;     // [0.73, 1.00]
  components: TraceComponentDto;
  calibrationVersion: string;  // e.g., "default-v1"
  calculatedAt: string;        // ISO 8601 timestamp
  createdAt: string;           // ISO 8601 timestamp
}

interface TraceError {
  message: string;
  code?: string;
}
```

**2. Create `nextjs/hooks/useTraceQuery.ts`**:
```typescript
export function useTraceQuery(demoId: string) {
  return useQuery({
    queryKey: ['trace', demoId],
    queryFn: async () => {
      const response = await fetch(`/api/demos/${demoId}/trace`);
      if (response.status === 404) {
        // Return null to indicate no TRACE (not an error)
        return null;
      }
      if (!response.ok) {
        throw new Error(`Failed to fetch TRACE: ${response.statusText}`);
      }
      return response.json() as Promise<TraceDto>;
    },
    retry: 1,
    staleTime: 3600000, // 1 hour (TRACE immutable once calculated)
  });
}
```

**Implementation notes:**
- Handle 404 by returning null (not throwing error)
- Type return as `TraceDto | null`
- Use existing React Query client from app context
- Retry once on network errors
- Cache aggressively (1 hour stale time)

**Definition of Done:**
- Types fully cover TraceDto schema
- Hook handles 404 gracefully
- TypeScript compilation clean
- No console warnings
