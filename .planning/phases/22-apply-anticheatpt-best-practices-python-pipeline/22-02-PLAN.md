## Architecture Reference (from 22-RESEARCH.md)

The modular pipeline processes data through four explicit stages:

```
1. _extraction_stage: Run all traditional feature extractors (aimbot, wallhack, etc.) + derivatives
2. _conversion_stage: Normalize derivatives and prepare tensor format
3. _augmentation_stage: Apply augmentation for training (identity for production)
4. _analysis_stage: Run TransformerSequenceExtractor + WeightedScorer to produce final label
```

Worker currently orchestrates features in process_job(). Waves 2-4 refactor this into explicit stages while maintaining backward compatibility.

## Context Window Design (D-18)

- Window size: 300 ticks (kill ± 150 ticks)
- Boundaries: Must respect kill-event locality; skip windows with multiple kills
- Positional encoding: Absolute tick numbers from demo start (not window-relative indices)
- Input shape: 300 ticks × 44 features per tick (existing CS2 parser format)

## Phase 20 Integration

Transformer is one feature input to WeightedScorer. Phase 20's evidence gates remain the baseline and are NOT overridden by transformer confidence. High transformer score alone does not trigger High review signal (Pitfall 3 in 22-RESEARCH.md).
