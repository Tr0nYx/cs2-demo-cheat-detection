# Phase 11 PLAN: Wave 1 — TRACE API Enhancements

**Objective**

Extend TRACE API with historical data and percentile calculations. Wave 1 creates backend infrastructure for trend analysis and peer comparison by exposing player TRACE history and calculating component percentiles.

**Purpose:** Clients can retrieve player's TRACE trend and see how their scores rank against peers (percentiles).

**Deliverable:** Production-ready API endpoints for TRACE history with percentile ranks and comprehensive testing.

## Task Details

### Task 1: Create PercentileCalculator Service

**File:** `symfony/src/Application/Service/PercentileCalculator.php`

**Purpose:** Calculate percentile ranks for TRACE components.

**What to build:**

**PercentileCalculator Class**

Constructor:
```php
public function __construct(TraceRatingRepository $repository)
```

Public methods:

1. **calculateComponentPercentiles(TraceRating $trace): array**
   - Input: A single TraceRating entity
   - Query all TraceRating records (or last 1000 for performance)
   - For each component (ekill, aim, kast, util, clutch):
     - Count rows where component_value > input_value
     - Calculate percentile: (count_lower / total) * 100
     - Return: [ekill_percentile, aim_percentile, ...]
   - Return format: `['ekill' => 75.5, 'aim' => 62.3, ...]`

2. **calculateTrustMultiplierPercentile(float $trustMultiplier): float**
   - Similar logic for trust multiplier rank
   - Returns: 0-100 percentile rank

3. **calculateTraceAdjustedPercentile(float $value): float**
   - Overall TRACE adjusted percentile
   - Returns: 0-100 percentile rank

**Implementation notes:**
- Use repository findAll() or query builder with LIMIT for performance
- Cache results (e.g., 5-minute TTL) to avoid recalculation on every request
- Handle edge cases: < 10 samples (return null or 50), exact matches
- Use database queries (not PHP loops) for performance
- Consider caching percentile results per component

**Error handling:**
- If no data available: return null or sensible default (50th percentile)
- Log calculation time for performance monitoring

**Definition of Done:**
- PercentileCalculator exists with 3 methods
- Percentiles calculated accurately (tested with known data)
- Type hints on all public methods
- Caching implemented for performance
- Docstrings explaining calculation approach

### Task 2: Create Query & Handler Pattern

**Files:**
- `symfony/src/Application/Query/GetPlayerTraceHistoryQuery.php`
- `symfony/src/Application/Handler/GetPlayerTraceHistoryHandler.php`

**Purpose:** Encapsulate player TRACE history retrieval logic (CQRS pattern).

**What to build:**

**GetPlayerTraceHistoryQuery Class** (immutable DTO)
```php
class GetPlayerTraceHistoryQuery {
    public function __construct(
        public readonly string $playerId,
        public readonly int $limit = 10,
        public readonly int $offset = 0,
        public readonly string $sortBy = 'date', // 'date' (desc) or 'date_asc'
    ) {}
}
```

**GetPlayerTraceHistoryHandler Class**

Constructor injection:
- TraceRatingRepository
- PercentileCalculator
- TraceHistoryMapper

Method:
```php
public function __invoke(GetPlayerTraceHistoryQuery $query): TraceHistoryCollection
```

**Handler logic:**
1. Validate playerId (UUID format or ID type)
2. Query TraceRatingRepository.findByPlayerId($playerId, limit, offset, sort)
   - Or use findByPlayerIdPaginated() if custom finder exists
3. For each TraceRating:
   - Use PercentileCalculator to add percentiles
   - Map to TraceHistoryDto (see Task 3)
4. Return TraceHistoryCollection with:
   - traces: array of TraceHistoryDto
   - pagination: {total, limit, offset, hasMore}

**Error handling:**
- If no traces found: return empty collection (not error)
- If playerId invalid: log and throw InvalidPlayerException (404)
- If offset/limit invalid: validate and throw ValidationException (400)

**Definition of Done:**
- Query and Handler classes exist
- CQRS pattern followed (consistent with existing codebase)
- Type hints on all methods
- Error handling for edge cases

### Task 4: Create TraceHistoryController

**File:** `symfony/src/Presentation/Controller/TraceHistoryController.php`

**Purpose:** HTTP endpoint for player TRACE history.

**What to build:**

**TraceHistoryController Class**

Route:
```php
#[Route('/api/players/{playerId}/trace-history', name: 'get_trace_history', methods: ['GET'])]
public function getTraceHistory(
    string $playerId,
    Request $request,
    QueryBusInterface $queryBus,
    SerializerInterface $serializer,
): Response
```

**Handler logic:**
1. Parse query params:
   - limit: int (10-100, default 10)
   - offset: int (default 0)
   - sortBy: string ('date', 'date_asc', default 'date')
   - Validate: limit > 0, offset >= 0, sortBy valid
2. Validate playerId format (UUID or int)
3. Create GetPlayerTraceHistoryQuery with params
4. Dispatch via queryBus.handle()
5. Get TraceHistoryCollectionDto result
6. Serialize to JSON with 200 response
7. Set Cache-Control: public, max-age=300 (5 min, history might change with new demos)

**Error handling:**
- 400 Bad Request: Invalid playerId format
- 400 Bad Request: Invalid query params (limit out of range, etc.)
- 404 Not Found: Player not found
- 500 Internal Server Error: Database error
- All errors use ApiProblem pattern

**Response headers:**
- Content-Type: application/json
- Cache-Control: public, max-age=300

**Type hints:**
- All parameters typed
- Return type: Response

**Docstring:**
- Explain endpoint, parameters, response codes

**Definition of Done:**
- Controller exists with getTraceHistory() method
- Route registered and accessible
- All error codes handled
- Type hints on all methods

## Threat Model & Mitigations

| Threat ID | Category | Component | Mitigation |
|-----------|----------|-----------|-----------|
| T-11-01-01 | Information Disclosure | Player history | API returns only TRACE (no PII). Access control enforced by existing AnalysisResult auth. |
| T-11-01-02 | Denial of Service | Percentile calculation | Caching (5-min TTL) prevents expensive recalculation. Pagination (max 100 results) prevents large result sets. |
| T-11-01-03 | Tampering | Percentile ranking | Percentiles calculated from trusted trace_rating table. No user input in calculation. |
