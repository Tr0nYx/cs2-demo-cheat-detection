<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API DTO -> frontend view model | Persisted result data may be partial, old, or aggregate-only |
| Feature metadata -> UI explanation | Technical method fields are provenance, not user-facing evidence by themselves |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Spoofing | player profile links | mitigate | Generate profile links only for real non-placeholder Steam IDs |
| T-25-02 | Tampering | result view model | mitigate | Do not alter scores, verdicts, TRACE, or persisted confidence; only reshape display data |
| T-25-03 | Repudiation | feature explanations | mitigate | Preserve raw method/evidence as secondary technical detail while adding plain-language summaries |
| T-25-04 | Information Disclosure | aggregate rows | mitigate | Label Steam ID 0 as demo-level aggregate and avoid player attribution |
</threat_model>
