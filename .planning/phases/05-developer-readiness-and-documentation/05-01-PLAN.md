Create a Makefile at repository root with the following structure:

PHONY declarations for: help, build, up, down, restart, clean, logs, test, test-all, test-php, test-python, test-ml, lint, format, analyze-demo, train

**Core targets (wave 1):**
- `make help`: Print all targets and descriptions using @echo with clear formatting. Example output should list target name, purpose, and any required arguments (e.g., "FILE=path/to/demo.dem").
- `make build`: Run `docker compose build` to build PHP and Python images.
- `make up`: Run `docker compose up -d` to start all services (nginx, php, postgres, redis, python_worker).
- `make down`: Run `docker compose down` to stop all services.
- `make restart`: Run `docker compose restart` to restart all services.
- `make clean`: Run `docker compose down -v` to stop containers and remove volumes; remove `data/models/`, `data/datasets/`, `data/demo-storage/*` (except .gitkeep).
- `make logs`: Run `docker compose logs -f` to tail all service logs.

**Test targets (wave 1):**
- `make test`: Alias for `make test-all` for convenience.
- `make test-all`: Run `make test-php`, then `make test-python`, then `make test-ml` in sequence. Fail fast on any test suite failure.
- `make test-php`: Run `docker compose exec -T php ./vendor/bin/phpunit --configuration phpunit.xml.dist` to execute Symfony tests. Ensure PHPUnit is installed in symfony/composer.json (verify dependency exists).
- `make test-python`: Run `docker compose exec -T python pytest python/tests/ --tb=short -v` to execute Python worker, feature, and parser tests. Exclude ML tests.
- `make test-ml`: Run `docker compose exec -T python pytest python/ml/tests/ --tb=short -v` to execute ML pipeline tests (if ml/tests exists; otherwise pytest python/ml).

**Advanced targets (wave 1, for documentation only—not required to work yet):**
- `make lint`: Run `docker compose exec -T php ./vendor/bin/php-cs-fixer --dry-run --diff .` (PHP) and `docker compose exec -T python pylint python/` (Python, if available).
- `make format`: Run `docker compose exec -T php ./vendor/bin/php-cs-fixer fix .` (PHP) and `docker compose exec -T python black python/` (Python, if black is installed).
- `make analyze-demo`: Accept FILE=path/to/demo.dem argument. Run a Python script that loads the demo, extracts features, and writes results to PostgreSQL (implementation in Phase 5-03). For now, create a stub that echoes "analyze-demo: Not yet implemented. Phase 5-03 will wire the analysis entrypoint."
- `make train`: Accept EPOCHS=50 and OUTPUT_DIR=data/models arguments. Run `docker compose exec -T python python python/ml/train.py --epochs $(EPOCHS) --output-dir $(OUTPUT_DIR)` (implementation via Phase 5-01 and Phase 4). For now, create a stub that echoes "train: Requires Phase 4 training entrypoint."

**Help output structure:**
```
Usage: make [target]

Core targets:
  up              Start all services (nginx, php, postgres, redis, python)
  down            Stop all services
  restart         Restart all services
  clean           Stop services and remove volumes and data
  logs            Tail Docker Compose logs
  test            Run all tests (PHP, Python, ML)
  test-php        Run PHP (Symfony) tests
  test-python     Run Python worker/feature/parser tests
  test-ml         Run ML pipeline tests
  help            Show this message

Advanced targets:
  build           Build Docker images (php, python)
  lint            Run linters (PHP-CS-Fixer, pylint)
  format          Auto-fix code style (PHP-CS-Fixer, black)
  analyze-demo    Analyze a local demo file (FILE=path/to/demo.dem)
  train           Train the ML model (EPOCHS=50, OUTPUT_DIR=data/models)

Examples:
  make up
  make test-all
  make analyze-demo FILE=demo.dem
  make train EPOCHS=100 OUTPUT_DIR=models/exp1
```

Use .PHONY to mark all targets as non-file targets. Use $(SHELL) := /bin/bash for consistent shell behavior on Windows and Unix.

**Constraints:**

- All docker compose commands must include the -f docker-compose.yml flag or assume it's in the current directory.
- Do not require manual environment setup; rely on docker-compose.yml environment variables.

**Reference decisions:**
- Per D-01, expose both core (build, up, test, clean) and advanced targets (lint, format, train) via help.
- Per D-02, core targets assume Docker-first (no local PHP/Python requirement).
- Per D-05, test targets are explicit and separate (test-php, test-python, test-ml).
- Per D-06, help output is verbose and explains each target.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Makefile → Docker | Makefile commands trust Docker CLI and docker-compose.yml configuration. |
| Docker → Local files | Docker volumes bind-mount local files; modified files affect container runtime. |
| Test execution | Test targets run inside containers; they read code from bind mounts and can write reports to local filesystem. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Makefile test targets | mitigate | Test targets use `docker compose exec -T` (non-interactive) to prevent prompt injection; no user input is embedded in commands. |
| T-05-02 | Information Disclosure | .env.example in git | accept | .env.example contains only non-sensitive defaults and comments; actual secrets (.env) are in .gitignore. |
| T-05-03 | Elevation | Docker build context | mitigate | Docker build runs as non-root app user per Phase 1; Makefile does not escalate privileges. |
| T-05-04 | Denial of Service | make clean removes volumes | accept | make clean is explicit and documented; developers understand the consequence. No automated trigger. |

</threat_model>
