6. **End-to-End Example (Walkthrough with Code)**
   - Scenario: Upload a sample CS2 demo, poll for results, retrieve analysis
   - Shell example (curl):
     ```bash
     # 1. Upload
     DEMO_ID=$(curl -s -X POST -F "file=@demo.dem" http://localhost:8080/api/demos | jq -r '.id')
     
     # 2. Poll status (with polling loop)
     for i in {1..30}; do
       STATUS=$(curl -s http://localhost:8080/api/demos/$DEMO_ID | jq -r '.status')
       if [ "$STATUS" = "done" ]; then break; fi
       sleep 2
     done
     
     # 3. Retrieve results
     curl -s http://localhost:8080/api/demos/$DEMO_ID | jq '.result'
     ```
   - Python example (requests library):
     ```python
     import requests
     import time
     
     # Upload
     with open("demo.dem", "rb") as f:
         resp = requests.post("http://localhost:8080/api/demos", files={"file": f})
     demo_id = resp.json()["id"]
     
     # Poll
     while True:
         status = requests.get(f"http://localhost:8080/api/demos/{demo_id}").json()
         if status["status"] == "done": break
         time.sleep(2)
     
     # Retrieve
     result = status.get("result", {})
     print(f"Suspicion Score: {result.get('suspicion_score')}")
     ```

7. **Architecture Overview (Text Description)**
   - High-level flow: Frontend → Symfony API → Redis queue → Python worker → PostgreSQL
   - Components:
     - Symfony API: Handles demo uploads, status tracking, result ingestion
     - Redis queue: Async job dispatch (demo analysis)
     - Python worker: Parses demos, extracts features, scores suspicion
     - PostgreSQL: Persists demos, results, player history
     - ML pipeline: Trains transformer model on CS2CD dataset (separate from analysis)
   - Data flow:
     - User uploads .dem → Symfony validates and queues → Python worker picks up job
     - Worker parses demo, computes feature scores (aimbot, wallhack, recoil, etc.)
     - Results written to PostgreSQL → Symfony serves to user via API
   - Example text:
     ```
     Symfony API validates uploads and dispatches analysis jobs to a Redis queue.
     The Python worker processes jobs asynchronously, parsing CS2 demo files,
     extracting behavioral features (aim patterns, recoil compensation, movement),
     and computing suspicion scores. Results are persisted to PostgreSQL and
     served via REST API. The ML pipeline (separate from real-time analysis)
     trains a PyTorch transformer on the CS2CD dataset for research and validation.
     ```
