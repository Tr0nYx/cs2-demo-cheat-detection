# Phase 9 PLAN: Wave 2 — Database Persistence & Calibration

**Objective**

Add production-ready persistence infrastructure for TRACE rating system. Wave 2 transforms the pure-Python TRACE calculation engine (Wave 1) into a persistent, queryable system by:

1. Creating dedicated database tables (trace_rating, trace_calibration) with proper foreign key relationships
2. Implementing calibration management logic (load, calculate, store calibration versions)
3. Integrating TRACE calculation into result_writer.py (the central persistence point)

**Purpose:** TRACE scores become queryable historical data, enabling future phases to build ranking, trend analysis, and calibration refinement features.

**Deliverable:** Production-ready persistence layer with 100% unit test coverage and working integration between Python calculator and Symfony database.

## Task Details

### Task 1: Create Doctrine Migrations for TRACE Tables

**File:** `symfony/migrations/Version20260517000000.php`

**Purpose:** Define database schema for TRACE persistence (trace_rating and trace_calibration tables).

**What to build:**

**Table 1: trace_rating** (main TRACE results, 1 row per player-demo analysis)
- id (BIGINT PRIMARY KEY, auto-increment)
- analysis_result_id (BIGINT UNIQUE NOT NULL FK → analysis_result.id ON DELETE CASCADE)
- player_id (VARCHAR(255), indexed alongside demo_id)
- demo_id (VARCHAR(255), indexed alongside player_id)
- calibration_version (VARCHAR(50), defaults to "default-v1")
- trace_base FLOAT (unweighted average before suspicion adjustment)
- trace_adjusted FLOAT (base × trust_multiplier)
- trace_normalized FLOAT (adjusted / calibration.global_average)
- trust_multiplier FLOAT (from D-06: clamped [0.73, 1.00])
- trace_percentile FLOAT (nullable, computed by calibration)
- round_count INT (from demo for reference)

**Component scores (normalized [0.3, 2.0]):**
- ekill, aim, kast, util, clutch (all FLOAT)

**Raw component values (for debugging):**
- ekill_raw, aim_cpq, aim_csq, aim_ttd, aim_scs, kast_percentage, clutch_attempts INT, clutch_wins INT

**Metadata:**
- calculated_at TIMESTAMP (when TRACE was calculated)
- created_at TIMESTAMP DEFAULT NOW()
- updated_at TIMESTAMP DEFAULT NOW()

**Indices:**
- UNIQUE on (analysis_result_id)
- INDEX on (player_id, calculated_at) for player history
- INDEX on (calibration_version) for version-based lookups

**Table 2: trace_calibration** (calibration version tracking and statistics)
- id (BIGINT PRIMARY KEY, auto-increment)
- version (VARCHAR(50) UNIQUE NOT NULL, e.g., "default-v1", "live-v1")
- sample_size INT (number of trace_rating rows used)
- global_average FLOAT (average trace_adjusted)

**Per-component statistics:**
- ekill_mean, ekill_stdev, ekill_p50, ekill_p75, ekill_p95 (and repeat for aim, kast, util, clutch)
- 25 columns total for component means, stdevs, and percentiles

**Metadata:**
- created_at TIMESTAMP (when calibration generated)
- locked BOOLEAN DEFAULT FALSE (future: mark as final)

**Indices:**
- UNIQUE on (version)
- INDEX on (created_at) for version history

**Migration implementation:**
- Follow Phase 3 pattern (Version20260516042700.php as reference)
- Use parameterized SQL for schema definition
- Include both up() and down() methods
- No data migration (new tables)

**Definition of Done:**
- Migration file syntax is valid (no SQL errors)
- Both tables defined with correct columns, types, indices
- Foreign key relationships established (analysis_result_id → analysis_result.id)
- Reverse migration (down()) removes both tables correctly

### Task 3: Implement CalibrationManager in Python

**File:** `python/scoring/trace_calibration.py`

**Purpose:** Manage loading, calculating, and storing calibration versions.

**What to build:**

**CalibrationManager Class**

Constructor:
```python
def __init__(self, db_conn: psycopg2.extensions.connection):
    """Initialize with database connection."""
```

Public methods:

1. **load_calibration(version: str) → dict[str, Any]**
   - Query trace_calibration for matching version
   - Return dict with all statistics (version, sample_size, global_average, component means/stdevs/percentiles)
   - If not found: return default calibration (version="default-v1", global_average=1.0, all means=1.0)
   - Always fallback, never raise

2. **get_active_calibration() → dict[str, Any]**
   - Query for most recent (created_at DESC) unlocked calibration
   - If < 100 trace_rating rows exist: return default calibration (D-04: 100-sample threshold)
   - Otherwise return latest calibration

3. **calculate_calibration() → dict[str, Any]**
   - Query all trace_rating rows
   - Calculate statistics (numpy.mean, numpy.std, numpy.percentile)
   - Build new calibration dict
   - Do NOT write to DB (caller decides)
   - Return dict

4. **store_calibration(calibration_data: dict) → str**
   - Generate new version string ("live-v{N}")
   - Insert into trace_calibration via parameterized query
   - Return version string

5. **should_recalibrate() → bool**
   - Return True if count >= 100 AND no recent calibration (< 24 hours)
   - Otherwise False

**Error handling:**
- Try/except with psycopg2.Error
- Log errors as JSON (structured logging)
- Re-raise after logging

**No dependencies** beyond psycopg2 and numpy (existing).

**Definition of Done:**
- CalibrationManager class exists with 5 public methods
- All methods use parameterized queries (no string concatenation)
- Type hints on all public methods
- Docstrings explaining defaults and formulas
- Error handling with logging

### Task 4: Update result_writer.py to Persist TRACE Output

**File:** `python/persistence/result_writer.py`

**Purpose:** Integrate TraceCalculator output into database persistence.

**What to build:**

Update ResultWriter.write_result() to:

1. **Extract suspicion_score** from scoring_summary.overall_score

2. **Initialize CalibrationManager:**
   ```python
   calibration_manager = CalibrationManager(self.db_conn)
   ```

3. **Load active calibration:**
   ```python
   calibration = calibration_manager.get_active_calibration()
   ```

4. **Calculate TRACE (if components provided):**
   ```python
   if trace_components:
       calculator = TraceCalculator()
       trace_result = calculator.calculate(components, suspicion_score, calibration)
   else:
       trace_result = None
   ```

5. **Persist TRACE to trace_rating table:**
   - Only if trace_result is not None
   - Use parameterized INSERT with all component values
   - Link via analysis_result_id (FK)
   - Error handling: log but don't fail analysis (TRACE is optional enrichment)

6. **Check for calibration recalculation (optional):**
   ```python
   if calibration_manager.should_recalibrate():
       new_cal = calibration_manager.calculate_calibration()
       calibration_manager.store_calibration(new_cal)
   ```

7. **Log TRACE persistence:**
   - JSON event with demo_id, trace_base, trust_multiplier, calibration_version

**Backward compatibility:**
- If trace_components is None, skip TRACE calculation
- Suspicion-only analysis still works
- No changes to existing AnalysisResult insert

**Definition of Done:**
- write_result() accepts trace_components and suspicion_score parameters
- TraceCalculator is instantiated and called
- TRACE results are inserted into trace_rating table
- Calibration is loaded and used
- Backward compatibility maintained
- Type hints and docstrings updated

## Threat Model & Mitigations

| Threat ID | Category | Component | Mitigation |
|-----------|----------|-----------|-----------|
| T-09-02-01 | Tampering | trace_rating table | All SQL uses parameterized queries (cursor.execute with %s). No string concatenation. |
| T-09-02-02 | Spoofing | player_id, demo_id | Fields copied from validated AnalysisResult. FK prevents orphaned records. |
| T-09-02-03 | Repudiation | calculated_at timestamp | Set by Python at calculation time, immutable in Doctrine. |
| T-09-02-04 | Denial of Service | Calibration recalculation | 100-sample threshold + 24-hour cooldown prevent expensive calculations. |
| T-09-02-05 | Information Disclosure | TRACE historical data | TRACE is research signal (per TRACE.md), not PII. Confidentiality enforced by data access controls (Wave 3+). |
| T-09-02-06 | Elevation of Privilege | Calibration lockdown | Version field UNIQUE prevents overwrites. Future versions appended only. |
