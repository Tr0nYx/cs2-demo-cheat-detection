# Phase 9 PLAN: Wave 1 — Python Foundation

**Objective**

Implement the Python foundation for TRACE (Tactical Round Action & Contribution Evaluation) rating system. This plan creates the core calculation engine that scores player impact across five components and applies trust adjustment from suspicion analysis. Output: TraceCalculator class, component extraction helpers, comprehensive unit tests validating all formulas.

**Purpose:** TRACE provides a transparent player impact rating independent of suspicion verdicts. This foundation enables downstream persistence (Wave 2), API exposure (Wave 3), and frontend display (Wave 4). The score answers "how much useful round impact did this player produce?" without merging with "did this behavior seem automated?"

**Deliverable:** Production-ready Python modules for TRACE calculation, tested against TRACE.md specification, ready for data pipelines.

### Task 2: Create TraceComponents extraction helpers for all 5 components

**File:** `python/scoring/trace_components.py`

**Purpose:** Extract all 5 TRACE components from parsed demo data and feature outputs.

**What to build:**

1. **Five extraction functions** (each returns normalized [0.3, 2.0]):

   **extract_ekill(kills_data, victim_weapons):**
   - Formula: ratio = victim_weapon_value / max(attacker_weapon_value, 1)
   - kill_value = min(sqrt(ratio), 2.0)
   - Modifiers: assists (+0.60 × kill_value if ≥35 dmg), death within 5s (×0.85), two kills within 5s (×1.10)
   - Knife: attacker_value = 1 (no div-by-zero)
   - Zero kills: return 0.73 (neutral)

   **extract_aim(aim_cpq, aim_csq, aim_ttd, aim_scs):**
   - Reuse existing aimbot.py feature outputs (cpq, csq, ttd, scs)
   - Formula: aim_raw = cpq*0.35 + csq*0.20 + ttd*0.25 + scs*0.20
   - Clamp inputs [0.0, 1.0], scale output [0.3, 2.0]
   - NO duplication of aimbot logic

   **extract_kast(kills, assists, survived_rounds, traded_within_5s, total_rounds):**
   - KAST-positive: kill OR assist OR survived OR traded within 5s
   - kast_percentage = kast_rounds / total_rounds
   - Scale: 0.73 baseline, up to 1.5 for high participation
   - Zero rounds: return 0.73

   **extract_util(flash_assists, enemy_blind_seconds, he_damage, molotov_damage, teammate_blind_seconds, unused_utility_at_death):**
   - Formula: util_raw = flash*2.0 + enemy_blind*0.5 + he*0.02 + molotov*0.015 - teammate_blind*1.0 - unused*0.001
   - Range [0.3, 2.0], default 0.5 for no utility

   **extract_clutch(1v1_wins, 1v2_wins, 1v3_wins, 1v4_wins, 1v5_wins):**
   - Multipliers: 1v1=1.0, 1v2=1.35, 1v3=1.65, 1v4=1.90, 1v5=2.10
   - No clutches: return 1.0 (neutral)
   - Multiple clutches: average across all

2. **Factory function** `extract_all_components(parser_output, features_output) -> TraceComponents`:
   - Combines parser events (kills, utility) + feature outputs (AIM) into one object
   - Handles missing keys with safe defaults

**Reference:**
- TRACE.md: Full component definitions and formulas section
- Phase 3: Feature extractor patterns (no duplication, reuse outputs)
- 09-CONTEXT.md: Decision D-01 (all 5 components in scope)

**Definition of Done:**
- All five extraction functions return [0.3, 2.0] values
- eKILL: AK kill discounted, Deagle kill rewarded, knife no crash, zero kills = 0.73
- AIM: Reuses aimbot.py outputs without recalculating
- KAST: 100% participation > 1.0, 0% < 0.73, baseline 0.73
- UTIL: Positive modifiers increase score, penalties decrease it
- CLUTCH: 1v1 win = 1.0, 1v5 win = 2.1, no clutches = 1.0
- extract_all_components() combines all five and handles missing keys
- Type hints and docstrings on all functions
- Safe numeric handling (clamp, avoid div-by-zero)

## Threat Model & Mitigations

| Threat ID | Category | Component | Mitigation |
|-----------|----------|-----------|-----------|
| T-09-01 | Tampering | Suspicion score input | Validate suspicion_score in [0.0, 1.0] before Trust calculation; clamp to boundary if corrupted |
| T-09-02 | Information Disclosure | TRACE reveals skill levels | TRACE is research signal only; Wave 4 UI labels "impact rating", not proof of cheating |
| T-09-03 | Denial of Service | Large component values | Clamp all inputs/outputs to [0.3, 2.0] before weighting; linear extraction time |
| T-09-04 | Elevation | Trust misused as proof | Document in code: Trust ≠ cheating proof; clamped range [0.73, 1.0] prevents false confidence |
| T-09-05 | Repudiation | No calculation audit trail | Wave 2 persistence includes calibration_version per rating for reproducibility |
| T-09-06 | Spoofing | Malicious parser output | Parser validated by Phase 3; extraction handles edge cases (missing keys, weapon unknown, zero kills) |
