For every `nextcode`, persist cursor advancement and queue the sharecode. Apply status/backoff for `caught_up`, `invalid_seed`, `auth_failed`, `rate_limited`, and `steam_unavailable`.
  </action>
  <acceptance_criteria>
    - Handler advances at most N sharecodes per run.
    - `202/n/a` marks caught up and schedules a later check.
    - `403` marks auth failed and stops retrying until reconnect/force.
    - `412` marks invalid seed/known code and stops retrying until user action.
    - `429`/`503` apply temporary backoff and do not disconnect.
    - Logs contain connection/user/status context but not `steamidkey`.
    - Handler does not mutate analysis scores, TRACE scores, labels, or model confidence.
  </acceptance_criteria>

<threat_model>
T-18-05: A tracking run could overload Valve's API or flood the local import queue after a user returns from a long inactive period.
Mitigation: due-connection planner, global command limit, per-user discovery limit, and backoff for `429`/`503`.

T-18-06: Invalid credentials could be retried aggressively and trigger Valve temporary blocking.
Mitigation: mark `auth_failed`/`invalid_seed` as user-action states and exclude them from normal planner selection.
</threat_model>
