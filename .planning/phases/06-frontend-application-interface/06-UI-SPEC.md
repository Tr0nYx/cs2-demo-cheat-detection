# Phase 6 — UI Design Contract

> Visual and interaction contract for the frontend web application. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Requirement Mapped:** UI-01 — User can inspect uploads, analysis status, and result explanations through a web UI.

---

## Design Principles

1. **Research Clarity** — Present technical analysis results with precision and without unnecessary chrome. Users are researchers analyzing detection signals, not marketing audiences.
2. **Explainability** — Every suspicion score, feature breakdown, and classification decision is visible and traced back to its source features.
3. **Minimal Friction** — Upload a demo file, see results fast. No required authentication, no heavy page loads.
4. **Data Integrity** — Analysis results are immutable once computed. UI reflects backend state, never local state.
5. **Accessible** — WCAG 2.1 AA minimum. Keyboard navigation throughout, proper semantic HTML, color-blind safe palettes.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 700 (bold) | 1.4 | Form labels, badges, tags, small UI text |
| Body | 16px | 400 (regular) | 1.5 | Main content, descriptions, feature labels, callouts, standard UI text |
| Section Heading | 18px | 700 (bold) | 1.3 | Section headings within pages, subsection titles |
| Page Heading | 28px | 700 (bold) | 1.2 | Page title, major headings |

**Font weights used:** 400 (regular), 700 (bold) only.

**Scale rationale:** 4-size scale for data-heavy analytical interface. Body text consolidated to 16px for clarity and consistency. Section hierarchy maintained through size progression (12px labels → 16px body → 18px section headings → 28px page headings) and weight distinction (400 = body text only, 700 = all headings and emphasized UI text).

## Key Screens & States

### Screen 1: Upload Page

**URL:** `/`

**Purpose:** Initial entry point. Users upload a CS2 `.dem` file and optionally provide a Steam Match ID.

**Layout:**
- Header: Logo + "CS2 Demo Cheat Detection" title
- Main content area: Centered card with upload form
- Footer: Link to GitHub, documentation

**Components:**
- File input (drag-and-drop + click to browse)
- Optional text input for Steam Match ID
- "Upload Demo" primary button
- Upload status indicator (file size, format validation)

**States:**
- **Idle:** Empty upload area with dashed border, placeholder text
- **Hover:** Subtle background color change, cursor pointer
- **Dragging:** Highlighted border, accent color
- **File Selected:** Show filename, file size, remove button
- **Uploading:** Progress indicator, disable button
- **Success:** Redirect to results page (or show processing message if analysis not instant)
- **Error:** Show error message (invalid format, file too large, etc.)

**Accessibility:**
- Keyboard: Tab to file input, Enter to trigger dialog
- Screen reader: File input with proper label
- Error messages announced via live region

---

### Screen 2: Results Page

**URL:** `/results/{demo_id}`

**Purpose:** Display analysis results for a completed or in-progress demo.

**Layout:**
- Header: Logo, breadcrumb navigation, timestamp
- Main content: Vertical stack of sections
- Right sidebar (desktop) or collapsible (mobile): Quick stats, verdicts

**Sections (Top to Bottom):**

1. **Demo Info Card** (sticky header area)
   - Demo ID (copyable)
   - Upload timestamp
   - Players detected in demo
   - Download original demo file button

2. **Overall Verdict Section**
   - Large verdict badge (Clean / Suspicious / Likely Cheating)
   - Overall suspicion score (0-100 scale, color-coded)
   - Brief explanation of what the score means

3. **Per-Player Analysis** (one card per detected player)
   - Player name + Steam ID
   - Verdict badge
   - Suspicion score (0-100)
   - Feature breakdown table:
     | Feature | Score | Interpretation |
     | Aimbot | 0-100 | {color-coded interpretation} |
     | Triggerbot | 0-100 | {color-coded interpretation} |
     | Wallhack | 0-100 | {color-coded interpretation} |
     | Recoil | 0-100 | {color-coded interpretation} |
     | Bhop | 0-100 | {color-coded interpretation} |
     | Session Consistency | 0-100 | {color-coded interpretation} |
   - Collapsible "Detailed Explanation" section (shows raw feature values, timestamps, round-by-round breakdown)

4. **Technical Metadata Section** (collapsible)
   - Demo file hash
   - Parser version used
   - Feature extraction timestamp
   - Weighting coefficients applied

**States:**
- **Processing:** Spinner + "Analysis running..." message
- **Complete:** All sections populated with results
- **Error:** Error state with retry button
- **Not Found:** "Demo not found" message with link back to upload

**Accessibility:**
- Landmark regions (header, main, aside)
- Heading hierarchy (h1 → h2 → h3)
- Color not the only means of conveying verdict (text labels + icons)
- Focus management: Tab through sections, collapsible panels keyboard-accessible

---

### Screen 3: History/Dashboard Page

**URL:** `/history`

**Purpose:** View all past analyses, search, filter, sort.

**Layout:**
- Header: "Analysis History"
- Filters area (horizontal bar): Date range, verdict filter, search by player/demo ID
- Table/Grid: List of past analyses
- Pagination (if list grows large)

**Table Columns:**
- Upload Date/Time
- Demo ID (copyable, links to results)
- Players (comma-separated)
- Overall Verdict (badge)
- Top Suspicion Score
- Action (view, download, delete)

**States:**
- **Empty:** "No analyses yet" empty state
- **Populated:** Sortable table with actions
- **Filtered:** Show active filters, result count
- **Loading:** Skeleton rows while fetching

**Accessibility:**
- Table has proper th/td semantics
- Sort buttons are keyboard-accessible
- Filter form has proper labels
- Results count announced to screen readers

---

### Screen 4: Error States & Dialogs

**404 Not Found:**
- Heading: "Analysis Not Found"
- Body: "The demo or analysis you're looking for doesn't exist or has been deleted."
- Button: "Back to Upload" or "View History"

**Upload Error Dialog:**
- Heading: "Upload Failed"
- Body: "{error message}"
- Button: "Try Again" or "Cancel"
- Dismiss: Close button (X) in top right

**Delete Confirmation Dialog:**
- Heading: "Delete Analysis?"
- Body: "Are you sure? This cannot be undone."
- Buttons: "Cancel" (secondary), "Delete" (destructive red)

**Analysis Error:**
- Heading: "Analysis Failed"
- Body: "The analysis encountered an error. Error: {error_code}. Please try uploading the demo again."
- Button: "Try Again" or "Back to Upload"

## Interaction & Navigation

### User Flow 1: Upload → Results

```
Start (/upload)
  ↓
[User drags file or clicks to browse]
  ↓
File selected → show filename + Upload button
  ↓
[User clicks "Upload Demo"]
  ↓
POST /api/demos (upload file)
  ↓
Success (202) → Redirect to /results/{demo_id}
  ↓
Results page polls GET /api/demos/{demo_id} until analysis completes
  ↓
Analysis complete → Display all sections
```

### User Flow 2: View History

```
Start (/history)
  ↓
[Page loads, fetches GET /api/demos (paginated)]
  ↓
Display table of past analyses
  ↓
[User clicks on a row or "View" button]
  ↓
Redirect to /results/{demo_id}
```

### User Flow 3: Delete Analysis

```
[User on history page clicks Delete]
  ↓
Confirmation dialog appears
  ↓
[User clicks "Delete"]
  ↓
DELETE /api/demos/{demo_id}
  ↓
Success → Remove row from table
  ↓
[If on results page] → Redirect to /history with toast: "Analysis deleted"
```

### State Transitions

- **Idle** → **Uploading** (user submits form)
- **Uploading** → **Processing** (backend receives file, starts analysis)
- **Processing** → **Complete** (analysis finishes, results available)
- **Processing** → **Error** (analysis fails or network error)
- **Error** → **Idle** (user clicks "Try Again")

### Polling & Real-Time Updates

- Results page polls `GET /api/demos/{demo_id}` every 2 seconds while `status === "pending"`
- Once `status === "done"` or `status === "error"`, stop polling and display results
- Optional: Use WebSocket for live updates (v2 enhancement)

## Responsive Design

### Breakpoints

| Breakpoint | Width | Device | Grid |
|------------|-------|--------|------|
| Mobile | 320px–639px | Phone | Single column |
| Tablet | 640px–1023px | iPad | Two columns |
| Desktop | 1024px+ | Desktop, large tablet | Three columns (sidebar layout) |

### Mobile-First Approach

**Mobile (320px–639px):**
- Single column layout
- Upload card full width
- Results sections stack vertically
- Sidebar becomes collapsible drawer (hamburger menu)
- Table becomes card view (one item per card)
- Button text stays concise ("Upload" not "Upload Demo")

**Tablet (640px–1023px):**
- Two-column layout for results (main + collapsed sidebar)
- Upload form still centered
- Table becomes horizontal with horizontal scroll if needed
- Touch targets: 44px minimum (buttons, links)

**Desktop (1024px+):**
- Three-column layout: Sidebar (200px) + Main (flexible) + Right panel (300px)
- Upload form: Centered, max-width 600px
- Results: Full grid view
- Hover effects on buttons, rows, cards

### Touch Optimization

- All interactive elements: minimum 44px height (buttons, links)
- Spacing between touch targets: minimum 8px
- File upload: Large drag-and-drop area (200px min height)
- Mobile: Remove hover effects, add press feedback (opacity change)

## Accessibility

### WCAG 2.1 Level AA Compliance

- **Color Contrast:** All text meets 4.5:1 (normal) or 3:1 (large) contrast ratio
- **Keyboard Navigation:** All interactive elements reachable via Tab, activated via Enter/Space
- **Screen Reader Support:**
  - All images have alt text or are marked decorative
  - Form inputs have associated labels
  - Live regions for status updates (uploading, analysis complete)
  - Landmark regions (header, main, nav, footer)
- **Focus Management:**
  - Visible focus indicators (2px outline, blue)
  - Tab order follows visual order
  - Focus trap in modals (can't tab outside)
  - Skip link to main content (optional but recommended)
- **Motion:** Reduced motion respected (CSS `prefers-reduced-motion`)
- **Color Independence:** Verdicts shown with text labels + icons + color (not color alone)
- **Readable Text:** 
  - Minimum 16px font size for body (upgraded from 14px for clarity)
  - Line height 1.5 for body text
  - Text not justified (left-aligned)
  - Sufficient spacing between lines and paragraphs

### Specific Implementations

1. **Skip to Main Content Link** (mobile-first, visible on focus)
2. **Form Labels:** Every input has `<label for="input-id">` (not just placeholder)
3. **Error Messages:** Associated with form fields via `aria-describedby`
4. **Live Regions:** Upload progress and analysis status use `aria-live="polite"`
5. **Modals:** Have `role="dialog"`, `aria-labelledby`, return focus after close
6. **Tables:** Have `<thead>/<tbody>`, proper `<th>` scope
7. **Icons with Meaning:** Have `aria-label` or are wrapped in labeled context
8. **Disabled Buttons:** Properly marked, not removed from tab order

## Implementation Guidance

### Recommended Stack

**Framework:** Next.js 14+ (App Router)
- Server-side rendering for SEO (optional)
- File-based routing
- Built-in image optimization
- Integration with Vercel for deployment

**Styling:** Tailwind CSS 3+
- Utility-first, rapid component building
- Paired with shadcn/ui component library
- Configuration-driven design tokens (colors, spacing)

**Components:** shadcn/ui (Radix UI)
- Pre-built, accessible, unstyled components
- Customizable via Tailwind
- No additional dependencies beyond React + Radix

**State Management:** 
- TanStack React Query (for API state)
- React Context (for UI state: modals, sidebar toggle)
- No Redux or Zustand needed for this phase

**HTTP Client:** 
- Axios or native Fetch API
- axios with interceptors for auth (if added later)

**Icons:** Lucide React
- Comprehensive, well-maintained, accessible SVG icons
- Tree-shakeable

**Forms:** React Hook Form + Zod
- Lightweight form validation
- Type-safe schema validation

**Charts (if needed in v2):** Recharts or Chart.js
- For trend visualization, feature score charts
- Optional for v1, prioritize tables first

### Setup Instructions

1. **Initialize Next.js project:**
   ```bash
   npx create-next-app@latest --typescript --tailwind --eslint
   ```

2. **Initialize shadcn/ui:**
   ```bash
   npx shadcn-ui@latest init --new-york --base-color-mode light
   ```

3. **Install additional dependencies:**
   ```bash
   npm install @tanstack/react-query axios react-hook-form zod lucide-react
   ```

4. **Create directory structure:**
   ```
   app/
     layout.tsx
     page.tsx (upload)
     results/[id]/page.tsx
     history/page.tsx
   components/
     ui/ (shadcn components)
     Header.tsx
     Sidebar.tsx
     VerdictBadge.tsx
     FeatureTable.tsx
   lib/
     api.ts (axios instance)
     hooks/ (custom React hooks)
   types/
     index.ts (TypeScript interfaces)
   ```

5. **API Integration:**
   - Create `lib/api.ts` with Axios instance pointing to backend `/api`
   - Use React Query for state management
   - Type responses from Symfony endpoints

### Environment Variables

Create `.env.local`:
```env
NEXT_PUBLIC_API_URL=http://localhost/api
```

### Development Workflow

1. **Local backend:** Symfony running on `localhost` (or Docker)
2. **Local frontend:** Next.js dev server on `localhost:3000`
3. **CORS:** Configure Symfony to allow requests from `localhost:3000`
4. **Testing:** Jest + React Testing Library for unit tests
5. **E2E:** Playwright or Cypress for end-to-end tests
