<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job queue → Worker | Untrusted JSON job payloads from Symfony; file paths could be malicious or missing |
| File system → Worker | Demo files on storage volume; could be corrupt, missing, or symlinked to sensitive paths |
| Worker → PostgreSQL | Worker writes error messages and feature data; SQL injection risk if not parameterized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Redis BRPOP job deserialization | mitigate | Use json.loads (safe, no code execution); validate demo_id and file_path exist before processing. Per A6 and D-02. |
| T-03-02 | Elevation of Privilege | File path access (../../../etc/passwd) | mitigate | File path comes from Symfony DB (not user-provided via API); combine DEMO_STORAGE_PATH + filename in sandboxed location. Python container runs as non-root user (Phase 1). |
| T-03-03 | Tampering | SQL injection via error messages | mitigate | Use psycopg2 parameterized queries (cursor.execute with %s placeholders); never string-format SQL. ResultWriter enforces this pattern. Per D-16 and security review. |
| T-03-04 | Denial of Service | Malicious demo file causes parser crash | mitigate | DemoParserAdapter validates structure and raises DemoParseError; worker catches and logs (no crash). All-or-nothing error handling per D-18. |
| T-03-05 | Information Disclosure | Stack traces leaked in logs | mitigate | Log exception messages only (str(e)); never log full stack traces to stdout. Stdout JSON is aggregated by container orchestration (Kubernetes). Per D-39 and security review. |
| T-03-06 | Information Disclosure | Demo file paths logged in production | mitigate | Log only demo_id (UUID), not full file path. Per D-40 security note. File path is internal/operational; hashing it adds no value. |

</threat_model>
