2. Create frontend/lib/hooks/useSensitivityTuner.ts:
   - Export function useSensitivityTuner(demoId: string, featureVectors: FeatureVectorsDto):
     * State: thresholds (FeatureThresholds, initial all 50)
     * Constants: COMPONENT_WEIGHTS = {aimbot: 0.25, wallhack: 0.25, triggerbot: 0.15, recoil: 0.20, bhop: 0.10, session: 0.05}
     * State: comparisonResult (SensitivityComparisonDto | null), for "Save Comparison" response (Wave 3)

3. Score calculation (local, instant):
   - Function calculateEstimatedScore(thresholds, vectors):
     * For each feature:
       - Convert slider [0, 100] to threshold [0, 1]: threshold_value = threshold_slider / 100
       - Compare: if vector_score > threshold_value, feature_triggered = 1, else 0
       - Example: If aimbot slider = 50 (threshold 0.5), and aimbot_vector = 0.92, then aimbot_triggered = 1 (0.92 > 0.5)
     * Calculate weighted sum: sum(feature_triggered * weight) for all 6 features
     * Result is suspicion score [0, 1]
   - Function setThresholds(newThresholds: Partial<FeatureThresholds>):
     * Merge newThresholds with current state
     * Re-run calculateEstimatedScore with new thresholds
     * Update estimated score display in real-time (< 100ms)

4. useMemo optimization:
   - Wrap calculateEstimatedScore in useMemo with dependencies [thresholds, featureVectors]
   - Prevents unnecessary recalculation on unrelated state changes
   - Ensures instant feedback (100ms max) even on slower devices

5. Save comparison mutation (deferred to Wave 3):
   - useMutation hook for POST /api/analytics/compare (empty for now, will be filled in Wave 3)
   - Signature: mutation.mutate({demo_id: demoId, adjusted_thresholds: thresholds})
   - On success: setComparisonResult(data) where data is SensitivityComparisonDto
   - Return object includes: thresholds, setThresholds, estimatedScore, mutation (isPending, mutate, data)

6. Type safety:
   - All threshold values explicitly typed as numbers [0, 100]
   - Feature vectors explicitly typed as [0, 1]

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend slider values → Score calculation | Trusted (fully client-side, no side effects); local recalculation has no persistence |
| Feature vectors from API → Frontend cache | Trusted (immutable after analysis); cached indefinitely with staleTime: Infinity |
| Estimated score → "Save Comparison" button | Untrusted (frontend can modify); backend will re-score with ground truth (Wave 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-06 | Tampering | User modifies feature vectors in local React state before send | Mitigate | Feature vectors read-only in component; save action POST to backend for re-scoring with ground truth (Wave 3) |
| T-15-07 | Information Disclosure | Feature vector values expose analysis internals | Accept | Feature vectors are public (derived from demo analysis); no sensitive PII exposed |
| T-15-08 | Spoofing | Browser claims estimated score without backend validation | Accept | Frontend score is preview only; persistence requires backend validation (Wave 3 POST /compare) |

</threat_model>
