1. Create symfony/src/Application/Service/SensitivityComparisonService.php:
   - Class SensitivityComparisonService with constructor dependency:
     * AnalysisResultRepository (for fetching demo analysis)
   
2. Public method: createComparison(string $demoId, string $userId, array $adjustedThresholds): SensitivityComparisonDto
   - Input validation:
     * demoId must be UUID format, throw InvalidArgumentException if not
     * userId must be non-empty string
     * adjustedThresholds must have all 6 keys: ['aimbot', 'wallhack', 'triggerbot', 'recoil', 'bhop', 'session']
     * Each threshold value must be integer in [0, 100], reject with InvalidArgumentException if not
   
   - Fetch analysis:
     * $analysisResult = $repository->findByDemoIdAndUserId($demoId, $userId)
     * Throw AccessDeniedException if not found or user mismatch (scope enforcement)
     * Throw LogicException if demo status !== 'done' (analysis must be complete)
   
   - Extract baseline score:
     * $baselineSuspicion = $analysisResult->getOverallSuspicion() (or $traceRating->traceAdjusted)
     * This is the system default using standard thresholds
   
   - Calculate tuned score with custom thresholds:
     * Convert adjusted_thresholds [0, 100] to [0, 1] range: threshold_value = threshold_slider / 100
     * For each feature:
       - Get feature_vector from $analysisResult (aimbotScore, wallhackScore, triggerbotScore, recoilScore, bhopScore, sessionConsistencyScore)
       - Compare: if feature_vector > threshold_value, triggered = 1, else 0
       - Example: aimbot_slider = 75 → threshold = 0.75 → if aimbot_score (0.92) > 0.75, triggered = 1
     * Calculate weighted sum: sum(triggered * COMPONENT_WEIGHTS[feature]) for all 6 features
     * Result: $tunedSuspicion [0, 1]
   
   - Calculate impact breakdown:
     * For each feature:
       - Impact = weighted_contribution_delta
       - Example: If aimbot_triggered changes from 1 (baseline, default threshold 0.5) to 0 (custom threshold 0.75):
         * Delta = 0 - 1 = -1
         * Impact = Delta * weight = -1 * 0.25 = -0.25
       - Store as: impactBreakdown['aimbot'] = -0.25
     * Precision: Round to 3 decimal places (e.g., -0.248 → -0.248)
   
   - Return SensitivityComparisonDto:
     * baselineSuspicion: float
     * tunedSuspicion: float
     * impactBreakdown: array<string, float> (6 entries, one per feature)
   
3. Default thresholds (for baseline calculation):
   - If using $analysisResult->getOverallSuspicion() directly, baseline is already computed by Phase 9 scorer
   - If need to recalculate baseline explicitly, use default thresholds = [0.5, 0.5, 0.5, 0.5, 0.5, 0.5] (50%)
   - Assumption: AnalysisResult stores overall_suspicion as ground truth (verify in code)

4. Error handling:
   - InvalidArgumentException: Invalid demoId, threshold values outside [0, 100], missing threshold keys
   - AccessDeniedException: User doesn't own demo (scope enforcement)
   - LogicException: Demo analysis not complete (status !== 'done')
   - All exceptions caught in AnalyticsController and returned as 400/403/422 HTTP responses
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend adjusted_thresholds → Backend POST | Untrusted (user can modify); server must re-validate and re-score |
| API response (tuned_suspicion) → User | Semi-trusted (server computed, but not persisted); display for informational purposes only |
| Comparison result → Database | Trusted (not persisted per D-06 in CONTEXT.md); transient session-only artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-09 | Tampering | POST adjusted_thresholds with invalid values ([-1, 200]) | Mitigate | Validate all threshold values in [0, 100] on server; reject with 400; don't process invalid input |
| T-15-10 | Elevation of Privilege | User posts demo_id they don't own | Mitigate | Always verify user_id from JWT matches demo owner; throw 403 if mismatch |
| T-15-11 | Information Disclosure | Comparison result leaks analysis internals | Accept | Comparison is derived from user's own analysis; no new information leaked beyond what user can see in TRACE card |
| T-15-12 | Denial of Service | POST /api/analytics/compare 1000x/sec | Mitigate | Enforce rate limit 10 req/min per user; return 429 if exceeded; log abuse attempts at WARNING level |
| T-15-13 | Tampering | Stored procedure injection in SQL queries | Accept | All queries parameterized via Doctrine QueryBuilder; no string concatenation |

</threat_model>
