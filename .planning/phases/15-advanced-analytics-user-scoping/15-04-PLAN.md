<objective>
Implement three player profiling trend metrics (consistency variance, improvement arc with outlier detection, weapon-specific strengths) with Redis-based caching and event-based cache invalidation. Enable users to understand their playstyle evolution over time.

Purpose: Trends provide temporal insights into player development and playstyle patterns. Consistency shows stability; arc shows improvement/degradation; weapons shows playstyle diversity. Caching ensures 100ms response times for repeat requests; invalidation ensures accuracy when new demos arrive.

Output: Three trend endpoints (GET /api/analytics/trends/consistency|arc|weapons), Redis cache with 1-hour TTL and event-based invalidation, frontend TrendChart component with area/line/heatmap visualizations, trends page pulling all three metrics.
</objective>

3. Create GetAnalyticsTrendHandler.php implementing MessageHandler:
   - Constructor dependencies:
     * TraceRatingRepository (for querying suspicion history)
     * AnalyticsCacheAdapter (for caching results, from Task 2)
     * Connection (Doctrine DBAL for raw SQL if QueryBuilder too complex)
   
   - __invoke(GetAnalyticsTrendQuery $query): ConsistencyTrendDto | ArcTrendDto | WeaponStrengthDto
     * Call private method matching metric type: computeConsistency(), computeArc(), computeWeapons()
     * Each method returns its specific DTO
   
   - Private method computeConsistency(string $userId, int $windowDays = 30): ConsistencyTrendDto:
     * Query trace_rating for user in last 30 days: WHERE player_id = ? AND calculated_at >= NOW() - INTERVAL '30 days'
     * Check demo count >= 5, return message if not
     * GROUP BY DATE_TRUNC('day', calculated_at):
       - AVG(trace_adjusted) → meanScore
       - STDDEV(trace_adjusted) → stddev
       - COUNT(*) → demoCount
     * Create VarianceBandDto for each day: mean, upper = mean + stddev, lower = mean - stddev
     * Detect volatility jumps: If |stddev[day] - stddev[day-7]| / stddev[day-7] > 0.20, flag date
     * Return ConsistencyTrendDto with bands + flagged dates
   
   - Private method computeArc(string $userId): ArcTrendDto:
     * Query all demos for user (no time window), ordered by calculated_at ASC
     * Check count >= 5, return message if not
     * Compute least-squares regression: X = ROW_NUMBER() OVER (ORDER BY calculated_at), Y = trace_adjusted
     * Calculate slope, intercept, R²:
       - slope = (N * Σ(X*Y) - Σ(X) * Σ(Y)) / (N * Σ(X²) - (Σ(X))²)
       - intercept = (Σ(Y) - slope * Σ(X)) / N
       - R² = 1 - (SS_res / SS_tot) where SS_res = Σ(Y_actual - Y_predicted)², SS_tot = Σ(Y_actual - Y_mean)²
     * Detect outliers: For each point, calculate predicted = slope * X + intercept, deviation = (actual - predicted) / stddev_residuals
       - Flag if |deviation| > 2 (2σ outlier)
     * Return ArcTrendDto with slope, intercept, R², outliers
   
   - Private method computeWeapons(string $userId): WeaponStrengthDto:
     * Query trace_rating JOIN analysis_result to get weapon data
     * Weapon extraction: Parse feature_data JSON or use demo's weapon_class field (verify in code)
     * GROUP BY weapon_class:
       - CASE weapon_name WHEN 'ak47' THEN 'Rifle' WHEN 'awp' THEN 'Sniper' ... END
       - AVG(trace_adjusted) → average suspicion per class
     * Return WeaponStrengthDto with all 4 weapon classes (or subset if user hasn't used all)

   - Weapons query: JOIN with analysis_result, needs index on (player_id, calculated_at)

| T-15-15 | Information Disclosure | Trend data exposes analysis algorithm details | Accept | Trends are derived from user's own TRACE scores; no new information beyond what user can already see |
